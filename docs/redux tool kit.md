# Как устроен Redux в проекте

## 1. Что такое Redux и Store?

**Redux** — это централизованное хранилище состояния приложения. Вместо того чтобы каждая страница хранила собственные копии записей, у нас есть одно общее хранилище — `store`.

**Store** — это центральное хранилище состояния приложения. В нём находится информация, которая нужна разным частям приложения. Например, в будущем состояние **Arterio** может выглядеть так:

```ts
{
  insight: {
    items: [
      {
        id: "1",
        title: "Новая идея",
        content: "Мои размышления...",
        createdAt: "...",
        updatedAt: "..."
      }
    ]
  },

  mood: {
    items: [
      // Записи настроения
    ]
  }
}
```

> То есть **Store** объединяет состояния разных бизнес-сущностей.

---

## 2. Что такое Reducer?

**Reducer** — это механизм, который определяет, как изменяется состояние.

Например, у нас есть сущность `Insight`. В её `slice.ts` мы описали три операции:
- Добавить запись.
- Изменить запись.
- Удалить запись.

Именно **reducer** определяет, что произойдёт с данными при каждой такой операции.

> **Reducer** — это не отдельное хранилище, а набор правил изменения состояния.

---

## 3. Что делает `configureStore`?

В нашем `store.ts` есть:

```tsx
export const store = configureStore({
  reducer: persistedReducer,
});
```

Здесь мы создаём центральный **Store**. Но откуда он знает, какие данные хранить и как их изменять? Мы передаём ему объединённый reducer:

```ts
const rootReducer = combineReducers({
  insight: insightReducer,
});
```

Таким образом, `configureStore` получает конфигурацию всего состояния приложения и создаёт единое хранилище.

---

## 4. Как Redux связан с React?

Сам по себе Redux не знает о React-компонентах. Чтобы React мог работать с Redux, мы подключаем `Provider`:

```tsx
<Provider store={store}>
  <App />
</Provider>
```

`Provider` делает **Store** доступным для компонентов внутри `App`.

---

## 5. Как Redux связан с `localStorage`?

Здесь появляется ещё одна технология — **Redux Persist**.

> **Важно:** сам по себе Redux Store ничего не записывает в `localStorage`. Это делает **Redux Persist**, который мы подключили к Store.

В нашем коде:

```ts
const persistConfig = {
  key: "root",
  storage,
};
```

А затем:

```ts
const persistedReducer = persistReducer(persistConfig, rootReducer);
```

**Redux Persist** оборачивает основной reducer и следит за изменениями состояния. Для восстановления состояния мы используем `PersistGate`:

```tsx
<PersistGate loading={null} persistor={persistor}>
  <App />
</PersistGate>
```

`PersistGate` не позволяет основному интерфейсу отобразиться до завершения восстановления сохранённого состояния.

### Как работает сохранение данных:
1. **Пользователь изменяет данные** — например, создаёт `Insight`.
2. **Redux Store** обновляет состояние.
3. **Redux Persist** перехватывает и сохраняет состояние.
4. **`localStorage`** записывает данные в браузере.

### Что происходит при следующем запуске?
1. **Redux Persist** восстанавливает данные из `localStorage`.
2. **Redux Store** получает сохранённое состояние.
3. **React** отображает восстановленные данные.
